# 攝影作品展示與相簿交付：最小產品實作規格

## 問題陳述

攝影師需要將 NAS 中已由 Lightroom 處理完成的 JPG，以清楚、完整且適合手機觀看的方式呈現，並讓訪客取得適合傳送或保留完整尺寸的照片。目前專案只有選片資料與視覺原型，沒有正式的發佈控制、圖片處理、固定網址或檔案交付功能。直接公開 NAS 資料夾也無法表達哪些相簿可以被探索、哪些僅供持有網址者存取，以及哪些不應發佈。

## 解決方案

實作採繁體中文、台灣用語的公開攝影網站，以中央白名單控制相簿發佈。首頁是依相簿日期由新到舊排列的相簿列表；訪客可進入自然比例相片列表與深色看圖器，取得瀏覽用 JPG、原始 JPG 或包含整本原始 JPG 的 ZIP。沿用已核准的 C 視覺方向，完整保留照片構圖，提供手機、平板、桌面體驗與固定相片網址。

## 使用者故事

1. 身為攝影師，我希望只有明確列入白名單並啟用的相簿會發佈，以免其他 NAS 內容意外曝光。
2. 身為攝影師，我希望應用程式唯讀存取 Lightroom 匯出的 JPG，以保留來源檔案不變。

6. 身為攝影師，我希望自行指定相簿標題與相簿日期，以正確呈現拍攝活動，而不依賴檔案時間。

## 實作決策

### 來源、設定與發佈

- 概念沿用既有領域詞彙：相簿（Album）、公開相簿（Public album）、未列出相簿（Unlisted album）、已發佈相簿（Published album）、相片（Photo）、瀏覽用 JPG（Display JPG）、原始 JPG（Original JPG）、相簿壓縮檔（Album archive）、相簿日期（Album date）。未列出不等於私密或受保護；任何持有網址的人均可存取。
- 中央設定為 UTF-8 JSON，頂層僅接受 `version` 與 `albums`，版本僅支援 `1`。每本必填 `folder`、`slug`、`title`、`date`、`status`，`cover` 選填。設定檔的既定位置沿用 #3 契約。
- 未知欄位、錯誤型別、不合法值、當下設定中的重複 `folder` 或 `slug` 均視為錯誤。未列入設定的資料夾不發佈，設定失敗不自動掃描或放寬白名單。
- `folder` 僅可指定相簿根目錄下一層資料夾，不接受絕對位置、巢狀位置或父層跳脫；固定讀取其中的 Lightroom 輸出子目錄。讀取與下載均須維持此來源邊界，不允許以編碼路徑或檔案連結繞過。
- `slug` 僅含小寫英文字母、數字與連字號；`title` 去除頭尾空白後不得為空，允許不同相簿同名。`date` 是有效西元 `YYYY-MM-DD` 日期，可晚於今天。
- `status` 僅接受 `disabled`、`public`、`unlisted`。公開相簿可被首頁探索；未列出相簿可直接開啟但不列入公開探索；停用或不在白名單的內容對外回傳 404，包含相片、衍生圖與下載。
- 已發佈相簿缺少來源資料夾、輸出子目錄、合格 JPG 或指定封面時，回報錯誤並退出，不載入部分成功結果。設定不存在、無法解析、版本或結構錯誤亦同。停用相簿仍驗證欄位，但不檢查 NAS 檔案存在性。
- 只收錄輸出子目錄第一層的 JPG／JPEG，副檔名不分大小寫；忽略其他檔案與子資料夾。原型選片的來源例外不延伸到正式產品。
- 以不分大小寫的檔名自然升冪排序，數字按數值比較；相等時再以原始檔名決定固定順序。不新增檔名大小寫或 Unicode 正規化規則，依實際檔案系統讀取。
- 指定封面必須是該相簿合格 JPG；未指定則使用排序後第一張。封面仍計入相片列表與相片數。首頁依相簿日期降冪，同日期先後不保證。
- 使用 #3 已核准的相簿與編碼檔名相片網址契約；不以相片排序索引作為永久識別。刪除設定後不保留歷史 `slug`，變更 `slug` 或檔名不承諾舊網址轉址。

### 瀏覽與視覺

- 首頁沿用核准 C：暖色紙面、細線、純文字 `Albums`；首本於平板與桌面跨列強調，下方採手機一欄、平板兩欄、桌面三欄。這是最新一本的視覺強調，不新增人工精選功能。
- 相簿內頁沿用暖色紙面，相片依自然比例排列，手機一欄、平板兩欄、桌面三欄；640px 以下一欄，其他視覺尺寸以核准原型為基準。不裁切照片，也不套用原型七本相簿或八張相片的樣本數量限制。
- 看圖器採深色背景，盡量保留大圖空間；底片縮圖等高、依比例調整寬度，提供目前相片指示與定位操作。
- 支援左右鍵、觸控滑動與 Escape 返回相簿；控制項有可辨識名稱、可見焦點，開關看圖器時管理焦點。固定相片網址可直接載入、重整與透過瀏覽紀錄返回合理畫面。
- 動態保持細微，遵循系統減少動態設定。原型的版型切換器、手動動態預覽開關與模擬提示不納入產品。
- 相簿及相片頁提供可供社群爬蟲取得的標題、網址與對應預覽圖中繼資料；相簿使用封面，相片使用對應相片。不以只有執行前端 JavaScript 才能看到的資料作為唯一預覽來源。不設分享按鈕。

### 圖片與交付

- 瀏覽用 JPG 自動縮放與最佳化，保持完整構圖；原始 JPG 下載內容須與 Lightroom 來源位元組一致。衍生圖與 ZIP 不寫回 NAS 來源。
- 單張提供「下載瀏覽用 JPG」與「下載原始 JPG」，說明分別為「適合瀏覽與日常傳送」及「Lightroom 匯出的完整尺寸 JPG」。
- 相簿提供「下載整本相簿 ZIP」，內容為該相簿全部合格原始 JPG，不含 RAW、其他相簿或來源以外檔案。
- ZIP 呈現準備、取消、完成與失敗狀態，可重試。可靠進度存在才顯示百分比，否則使用不定進度。完成表示 ZIP 已備妥可下載，不表示已儲存至訪客裝置。
- 同一套已發佈相簿解析規則應涵蓋頁面、圖片、下載與預覽，避免各入口有不同白名單判斷。
- 目前沒有正式應用程式或可沿用的模組介面。實作責任包括啟動時設定與相簿載入、HTTP 頁面及檔案交付、圖片與 ZIP 產生、瀏覽器互動；不要求依責任逐一建立抽象層或服務。
- 框架、圖片尺寸／品質、ZIP 產生與快取方式由實作選擇最小可行方案；此規格不預先加入資料庫、背景佇列或多服務架構。

### 次要狀態：沿用 #1 結案預設

這些是代理在 #1 結案時補齊的實作預設，與攝影師明確核准的 C 主畫面有所區別，不能宣稱經過逐項視覺核准。

| 狀態 | 介面 |
| --- | --- |
| 沒有公開相簿 | 「目前尚無公開相簿」。 |

| ZIP 完成 | 「ZIP 已準備完成」，可取得 ZIP。 |

## 測試決策

- 已由使用者確認測試邊界：以啟動真實應用程式並提供暫存相簿來源與設定，作為共同整合入口。透過 HTTP 與瀏覽器驗證外部行為，不綁定內部函式、類別或目錄結構。
- 此入口涵蓋設定／來源載入、發佈控制、頁面與圖片回應、JPG／ZIP 交付；瀏覽器則觀察同一應用程式的使用者操作與視覺結果，不另建只供測試使用的產品介面。
- 啟動測試覆蓋有效設定、無效 JSON／版本／欄位／日期、重複識別、來源與封面缺漏，以及停用相簿不要求來源存在；斷言退出結果與無部分發佈。
- HTTP 測試使用公開、未列出、停用與未設定相簿；驗證首頁探索、直接網址、404、編碼檔名、路徑跳脫拒絕與所有下載入口一致的發佈限制。
- 使用少量可重現的橫幅、直幅、數字檔名、混合大小寫副檔名及非 JPG 範例，驗證自然排序、封面回退、計數與完整比例。測試不依賴私人 NAS 或公開私人檔名。
- 比對原始 JPG 下載位元組；解開 ZIP 比對檔案集合與內容；驗證瀏覽用 JPG 能解碼且保留比例，並檢查來源檔案未被修改。
- 不執行頁面 JavaScript 的 HTTP 讀取應能取得相簿／相片對應的社群預覽中繼資料。
- 瀏覽器檢查手機、平板、桌面 C 版型、長相簿捲動、看圖器、底片定位、鍵盤、滑動、焦點返回、直接網址與重整、瀏覽紀錄及減少動態。核對完整構圖與欄數，不對每個 CSS 值建立脆弱斷言。
- 驗證 ZIP 真實準備、取消、完成、失敗及重試；驗證載入失敗與空列表。必要時於檔案或網路邊界製造可重現失敗，不以原型的計時假進度作為功能驗證。
- 既有專案無正式測試套件。原型紀錄的建置與語法檢查是視覺資產證據，不能視為正式下載、HTTP 或瀏覽器測試已通過。

## 不在範圍內

- 本票產出規格；後續由實作票券交付上述正式功能。正式環境部署、NAS 掛載與憑證佈署不屬於本規格的功能實作驗收。
- RAW 交付、管理後台、帳號、登入、密碼保護相簿。
- 攝影師介紹、人工精選管理、分類、聯絡表單、多語系、標誌設計。
- 社群直接發文、分享按鈕、浮水印、使用權介面、逐相簿下載權限。
- 手動拖曳相片排序、歷史網址登錄或轉址管理。
- 重開視覺方案評選，或將原型模擬流程直接當成正式交付。
